# SF Tech Week City (repo: city-in-ink) — notes for Claude Code

- **Name:** the game is **SF TECH WEEK CITY**. `wireBrand()` in `build.mjs` renames the player-visible strings at build time (title, masthead, loading overlay, flagship airship, `.ics` PRODID) and fails loudly if a target string moved; the original in `source/` still says "City in Ink" on purpose.

- **No `npm install`.** The build uses Node built-ins only. Node ≥ 20 (verified on 24).
- **Local development:** `npm run build:local` → `dist-local/`, then serve that directory with any static server (e.g. `python3 -m http.server 8790 --directory dist-local`) and open http://localhost:8790/. There is no watcher — rebuild after every edit.
- **Never open `dist/` locally.** `npm run build` produces the Chrona-hosted build, which refuses to run outside Chrona's iframe by design (`A trusted HTTPS host origin is required`). That is not a bug to fix.
- **Edit surfaces:** add-on modules at the repo root — `multiplayer.js`, `events-sync.js`, `gull-cluster-route.mjs`, `chrona/` — edit directly. The original game is `source/part-*.txt` (one 24 MB HTML split into 4 MiB parts); after editing it run `node build-hosted.mjs --accept-source-update` and commit `source/manifest.json` together with the parts.
- Builds patch the original with exact-match string replacements (`build.mjs`, `events-build.mjs`). A `patch target changed` error means a source edit broke a patch — fix the patch or the edit; never bypass the check.
- **Expected in standalone mode, not bugs:** CORS errors for `cdn.tech-week.com` posters; `/events.json` 404 (the saved data in `data/` is used); sign-in and multiplayer go to the *test* control plane; `/assets/airship.glb` and `/assets/brand/techweek-logo.svg` 404 (optional assets with built-in fallbacks, also 404 in production).
- **Single-file preview:** `npm run build:artifact` → `dist-artifact/` (`build-artifact.mjs` + `artifact-assets.js`): the whole game in one ~10.8 MB HTML for claude.ai Artifacts / no-network hosts — geometry re-encoded and decoded in-page, event snapshot embedded, add-ons inlined, no multiplayer. Publish `dist-artifact/city-in-ink.artifact.html` (wrapper stripped) to an Artifact, `index.html` anywhere else.
- **Never commit** `.chrona/`, `dist/`, `dist-local/`, `dist-artifact/`.
- **A merge to `main` is a production deploy.** `.github/workflows/chrona-release.yml` → `.github/chrona-release.mjs` builds the commit, then approves, merges and **publishes** it to the live Chrona World `e9ef2f62-a6e0-47f2-8795-c2941cbc433a` on https://chrona.world. Measured latency: about 30 seconds from push to live. No human confirms it.
  - **Never push or merge to `main` unless the user asked for this change to go live in this message.** "Commit it", "push it", "done?" are not release requests — commit to a branch and say what would go live. When you do release, say plainly that the live game is about to change.
  - **Never** dispatch that workflow on a non-`main` branch (`gh workflow run chrona-release.yml --ref <branch>`): it would release that branch to the live World and the next push to `main` would silently revert it.
- **Working on a branch publishes nothing.** To show work in progress, build a preview with `CHRONA_SUBMIT_STOP_AT=preview node .github/chrona-release.mjs` (README → "Automatic release from GitHub (CI)"). Behind a proxy, run the Chrona CLI with `NODE_USE_ENV_PROXY=1` — Node ignores `HTTPS_PROXY` by default and the call stalls for 120s without it.
- **Verify before reporting done.** A change to the game is finished only when you rebuilt it and loaded it in a browser: the city renders, you can enter it, and the console shows no errors beyond the expected ones above. "The build succeeded" is not verification.
